## 바뀐 계산 방법

새 기본 방법은 **projected quantum kernel**입니다. 실제 연결 그래프와 불량 큐빗·게이트 정보를 확인해 큐빗을 작은 독립 블록으로 나누고, 블록 안에만 데이터 회전과 CZ 게이트를 적용합니다. 각 입력 상태에 대해 모든 큐빗의 X·Y·Z를 각각 측정합니다. 이처럼 국소 관측값을 고전 커널 함수의 입력으로 쓰는 방법은 IBM의 공식 projected-kernel 예제에 설명돼 있습니다. 이 프로젝트의 블록 회로와 검증 예산은 별도로 설계한 것이며 해당 예제의 실험 성능을 재현했다고 주장하지 않습니다. [IBM 공식 projected kernel 설명](https://quantum.cloud.ibm.com/docs/en/tutorials/projected-quantum-kernels)

큐빗 q의 측정 벡터를 `r_iq = (<X>, <Y>, <Z>)`라고 할 때 다음 고정 함수를 사용합니다.

```text
D(i,j) = Σq ||r_iq − r_jq||² / (2 × 큐빗 수)
K(i,j) = exp(−gamma × D(i,j)), gamma = 1
```

큐빗 수로 나누는 정책과 gamma는 결과를 보기 전에 고정했습니다. 작은 블록은 고전적으로 계산 가능하므로 정확한 블록별 시뮬레이터 결과를 별도 기준값으로 제공합니다. 전체 156큐빗 statevector를 생성하거나 시뮬레이터 값을 실측 행렬에 대입하지 않습니다. 같은 입력 벡터의 RBF 값인 **대각선 1은 수학적 정의**이며, 잡음 없는 하드웨어 self-fidelity를 측정했다는 뜻이 아닙니다. 실제 반복성은 별도로 제출한 동일 입력 대조군으로 확인합니다.

새 입력 N개당 회로는 `3N + 5`개입니다. 각 입력의 XYZ `3N`개, 첫 입력을 따로 반복하는 XYZ 3개, 모든 큐빗을 0/1로 준비하는 판독 대조군 2개입니다. 판독 대조군은 상태 준비와 판독을 합친 오차를 관측하며 순수한 검출기 오차만 분리하지 않습니다. 원시 기대값에 판독 보정이나 Bloch-ball 투영을 적용하지 않았습니다.

## 오차와 해석 범위

상태 준비·판독 대조군의 평균 오차는 **1.9165%**였지만 균일하지 않았습니다. 물리 큐빗 72는 0 준비에서 **22.9492%**, 1 준비에서 **38.5742%**의 오류가 관측됐습니다. 두 준비 조건 중 더 큰 오차가 5%를 넘는 큐빗은 15개, 10%를 넘는 큐빗은 7개였습니다. 이 기준은 진단용이며 장비의 공식 불량 판정이나 검증된 품질 통과 기준은 아닙니다. 모든 요청 큐빗을 사용했고 불리한 관측값을 제거하거나 임의로 보정하지 않았습니다. 큐빗별 수치와 구간은 화면과 원본 보고서에서 확인할 수 있습니다.

개별 Pauli 기대값에는 주변 이항 관측의 Wilson 95% 구간을 제공합니다. 커널에는 원시 bitstring 전체를 재표집한 64개 bootstrap 결과의 **2.5–97.5 백분위 범위**를 기록합니다. 이는 이상적 또는 실제 물리적 커널의 보정된 신뢰구간이 아닙니다. 재표집하면 제곱 거리에 shot 잡음이 추가되어 커널이 더 작아질 수 있고, 관측 점추정이 해당 범위 밖에 있을 수 있습니다. 실제 이번 결과에서도 이 현상이 나타났습니다. 판독 편향·시간 변화·보지 못한 결과는 이 범위에 포함되지 않습니다. 같은 입력 반복 대조군과 shot 잡음 바닥을 함께 해석해야 합니다.

Projected 방법도 회로 깊이, 얽힘, 입력 분포와 하드웨어 잡음에 따라 구분력을 잃을 수 있습니다. 이 방법을 보편적인 잡음 해결책으로 취급하지 않습니다. [양자 커널의 집중 현상 연구](https://www.nature.com/articles/s41467-024-49287-w)

**계산 대상은 RDKit 분자 기술자의 유사도입니다.** 단백질 좌표, AF3 복합체 특징, 전자 Hamiltonian 또는 실험 친화도 라벨을 이번 회로에 넣지 않았습니다. 결합 에너지·약효·독성 또는 후보의 우열을 이 행렬만으로 판단하지 않습니다. 많은 큐빗에 특징을 반복 배치한 것은 새 생물학 정보를 추가한 것이 아닙니다.

## 원시 자료 검증과 운영

제출 전에 실제 bound 회로의 QPY, PUB별 역할·입력 인덱스·측정축, 물리 큐빗과 classical bit 매핑을 저장했습니다. 완료 후 원시 bitcounts를 SHA-256으로 고정한 파일에 보존했습니다. 결과를 다시 열 때 입력 기록과 회로·원시 파일의 해시·크기를 검사합니다. 실패나 일부 제출은 누락값을 0으로 채우지 않고 기록하며 자동 재제출하지 않습니다.

독립 감사기는 backend의 수치 계산 함수를 호출하지 않고 정수 bit 연산으로 Bloch 기대값·Wilson 구간을, 별도 NumPy 계산으로 작은 블록의 이상적 상태·RBF·대조군·재표집 범위를 다시 계산했습니다. 실제 bound QPY의 측정 매핑과 gate를 확인하고 블록별로 실행해 입력·basis 구현도 검사했습니다. [실제 실행 기록](quantum-projected-verification.json), [독립 원시 자료 감사](quantum-projected-independent-audit.json)

분석 화면의 양자 패널은 기존 fidelity와 새 projected 결과를 구분하고 관련 재분석 기록을 함께 표시합니다. **양자 단계만 다시 계산**하면 보존된 특징값·입력 순서를 서버에서 대조한 뒤 별도 작업을 생성합니다. 전체 LLM/AF3 분석을 다시 실행하지 않습니다. 연구 기록에서도 같은 결과를 선택할 수 있습니다. 작은 비영값과 0회 관측은 표시 형식을 구분합니다.

| API | 동작 |
| --- | --- |
| `POST /api/quantum/plan` | 방법·최대 가용 폭·회로·shot·시간 상한을 조회; 제출 없음 |
| `POST /api/quantum/run` | 명시한 방법으로 별도 작업 생성·실행 |
| `GET /api/quantum/results?source_analysis_id=…` | 원본 분석에 연결된 재계산 기록 |

새 API와 분석 워크플로의 기본은 `kernel_method="projected"`이며, Python library의 기존 기본 `fidelity`와 schema 1 저장 자료 호환은 유지했습니다. `source_analysis_id`로 원본과 연결할 때 특징값이나 물질 순서가 다르면 실행을 거부합니다.

```bash
# 보존한 실제 IBM 작업만 조회
.venv/bin/python scripts/verify_projected_quantum.py --refresh

.venv/bin/python scripts/audit_projected_quantum.py \
  --manifest runtime/f1b0f1c6867b4d21b40193e65ab980bf/quantum.json \
  --verification-report docs/quantum-projected-verification.json \
  --output docs/quantum-projected-independent-audit.json
```

실제 제출은 이미 완료했으므로 같은 검증 스크립트의 `--execute` 반복 호출은 거부됩니다. 소프트웨어 회귀 검사와 실측·브라우저 검증 기록은 [변경 검증 기록](quantum-projected-software-verification.json)에 구분해 보존합니다.
