# 대규모 천연물·한약 연구 데이터와 후보 탐색

2026-09-07 구현. 실행 화면의 **대규모 탐색**에서 원천 수집, 구조 검색, 생물종/성분 필터, 후보 캠페인, 실제 처리 수치, 중단·재개, 분자 스튜디오 연결을 사용합니다. 최종 실측은 [검증 기록](discovery-verification.json)에 저장합니다.

## 실제로 가져오는 자료

COCONUT와 LOTUS에는 식물 외 생물의 천연물도 포함됩니다. 자료 전체를 한약재에서 검증된 성분으로 분류하지 않습니다. LOTUS의 생물종과 문헌은 원천에서 보고된 출현 정보이며, 특정 약재 제품의 함량·순도·약효를 의미하지 않습니다. 서로 다른 연구의 출현 기록은 구조가 같더라도 따로 보존합니다.

원본 다운로드는 `runtime/discovery/downloads/`, 원본 해시와 수집 보고서는 해당 작업의 아티팩트 디렉터리에 보존됩니다. COCONUT/LOTUS는 릴리스를 고정하고, ChEMBL API 응답은 조회 시점의 페이지를 원본 JSON으로 보존합니다. ChEMBL의 페이지들이 하나의 트랜잭션 스냅샷이라고 주장하지 않습니다. 배포 패키지에는 실행 코드·원천 정의가 들어가며, 수 GB의 로컬 연구 데이터는 별도로 관리합니다.

## 한글 약재명 검색

국내 공공 보유 약재 색인의 70페이지·691행을 확인해 **569개 한글 이름**을 원천에 보고된 학명 검색으로 연결했습니다. 예를 들어 인삼은 `Panax ginseng`, 황금은 `Scutellaria baicalensis`로 검색합니다. 감초처럼 여러 기원종이 확인된 경우에는 속 단위로 넓힌 검색임을 표시합니다. 처방·광물·미해결 표기·의심되는 철자는 자동으로 식물 학명으로 바꾸지 않습니다. [수집 범위와 해석](herb-aliases.md).

## 수집과 검색

```bash
# 한도 옵션을 생략하면 해당 공개 릴리스 전체 처리
uv run herbfold discovery fetch lotus-2026-04
uv run herbfold discovery fetch coconut-2026-09
uv run herbfold discovery fetch chembl-approved
uv run herbfold discovery status

# 사용자 자료도 원래 출처·라이선스를 명시해 스트리밍으로 추가
uv run herbfold discovery import /path/to/compounds.csv.gz \
  --source-id my-release --source-url https://example.org/dataset --license 'CC BY 4.0'
```

파일 형식은 CSV, TSV, SMILES, SDF 및 gzip을 지원합니다. ZIP은 하나의 CSV가 포함된 경우 안전한 파일명으로 추출합니다. 다운로드 체크섬과 ZIP CRC를 확인하며 실패를 완료로 바꾸지 않습니다. 수집은 500행 단위로 커밋하고, 잘못된 구조는 집계합니다. 재시도 시 원본을 다시 읽지만 이미 저장한 구조/원천 기록은 중복 추가하지 않습니다. 중단 지점의 압축 바이트부터 이어받는 기능은 구현하지 않았습니다.

구조 정체성은 입체 SMILES와 전체 InChIKey로 확인합니다. 염, 전하, 동위원소와 해석 가능한 입체화학을 수집 단계에서 보존합니다. 표준 InChI가 같은 일부 호변이성질체는 같은 정체성으로 묶이고 원본은 출처 레코드에 남습니다. 후보 생성 단계의 작은 분자 표준화는 별도로 실행됩니다.

검색은 이름·동의어·생물명·분류·원천 ID·InChIKey를 대상으로 합니다. 예: `Scutellaria baicalensis`, `Coptis chinensis`, `Panax ginseng`, `Glycyrrhiza`, `Zingiber officinale`. 검색 수치는 데이터가 실제로 가진 기록에서 계산합니다.

## 후보 캠페인

1. 천연물 원천과 생물종/성분 검색 범위를 고릅니다.
2. 기존 약물 또는 가져온 ChEMBL 비교군, 실제 부모 분자 수를 정합니다.
3. 목표 수와 시도·시간·저장량 예산을 지정합니다.
4. 작은 묶음으로 BRICS 절편을 결합하고 화학 구조를 검사합니다.
5. 두 부모의 서로 다른 절편 기여, 입력 부모와의 차이, 계산 물성 필터를 확인합니다.
6. 캠페인 안에서 중복을 제거한 후보만 보존합니다. 출처·부모·버전·커서를 함께 기록합니다.
7. 선별 후보를 3D 스튜디오에서 보거나 JSON으로 내보내고, 선택한 소수의 구조에 기존 Astra 분석·AF3·실측 검증 흐름을 적용합니다.

[RDKit BRICS 규칙](https://www.rdkit.org/docs/source/rdkit.Chem.BRICS.html)을 사용하되, 대규모 캠페인은 두 부모의 말단 절편을 한 번 결합하는 보수적인 방법입니다. 모든 가능한 분자나 모든 합성 반응을 열거하지 않습니다. 말단 절편 두 개의 각 연산에서 적용 가능한 결합 규칙과 결과 수를 제한하여 재귀적 조합 폭발을 막습니다. 완전한 구조만 저장하며, 절편 연결점을 임의 원자로 숨기지 않습니다.

```bash
# 실제 실행량은 목표 개수와 별도. 기본 조회 부모 범위를 먼저 검증합니다.
uv run herbfold discovery campaign \
  --name '황금 기원종 후보 탐색' --seed-source lotus-2026-04 \
  --seed-search 'Scutellaria baicalensis' --seed-limit 200 \
  --reference-limit 50 --target-count 1000000 \
  --max-attempts 100000 --max-runtime-seconds 3600 --max-storage-mb 1024

# Ctrl+C는 커밋한 후보와 커서를 유지하고 일시정지합니다.
uv run herbfold discovery resume CAMPAIGN_ID

# QED 상위 결과를 JSONL로 내보냅니다. QED는 약효 순위가 아닙니다.
uv run herbfold discovery export CAMPAIGN_ID --limit 1000 --output shortlist.jsonl
```

한 캠페인의 부모 스냅샷은 최대 10,000개이고, HTTP 화면에서는 천연물 최대 9,000개·약물 최대 500개입니다. 더 큰 원천은 `--seed-after-id`를 이용해 안정적인 구조 ID 구간으로 나눌 수 있습니다. `--seed-offset`은 단순 원천 행 건너뛰기이며 매우 깊은 위치에는 ID 커서를 권장합니다. 사용자 등록 원천도 `--seed-source my-release`로 선택할 수 있으며, 이때 천연물 기원은 사용자 선택에 따른 미검증 분류로 남습니다. 캠페인 간 전역 중복 제거는 아직 없으므로 여러 캠페인의 보존 수를 더해 고유 물질 수라고 보고하면 안 됩니다.

현재 기본 필터는 분자량 120–650, logP −2–6, TPSA ≤180, QED ≥0.25입니다. PAINS/Brenk 경고도 기록합니다. 이 범위에 맞지 않는 천연물은 원천 라이브러리에서 지우지 않습니다. 필터는 계산상 우선순위 도구이며 합성 가능성·안전성·약효의 증거가 아닙니다.

## 표시하는 숫자의 의미

| 항목 | 의미 |
| --- | --- |
| 요청 목표 | 최대 1억 개까지 지정 가능한 목표; 확보한 결과 수 아님 |
| 시도 | 절편 결합 시도와 생성 불가능한 부모 쌍의 처리 |
| 생성 | 화학적으로 해석 가능한 구조 제안; 중복 포함 |
| 보존 | 부모 계보와 필터를 통과하고 캠페인 내에서 중복 제거한 구조 |
| 필터 제외 | 잘못된 구조, 계보 미충족, 기존 부모, 물성 필터 등 |
| 중복 | 이미 보존한 후보와 같은 구조 |

유한 조합이 끝나면 `exhausted`, 예산에 도달하면 `budget_exhausted`, 목표를 실제로 채우면 `completed`입니다. 오류는 `failed`와 사유로 기록합니다. 서버 재시작 후 실행 중 캠페인은 일시정지하여 명시적인 재개를 기다립니다. 각 배치의 후보·카운터·커서는 같은 트랜잭션으로 커밋합니다. 프로세스 강제 종료로 완료되지 않은 배치는 다시 계산하며, 이전 커밋은 유지됩니다.

## 수백만–수억 규모의 범위

큰 목표를 설정할 수 있도록 메모리 사용을 배치로 제한했고, 저장과 중복 검색에 디스크 인덱스를 사용했습니다. **1억 개 고유 후보를 실제 생성하거나 1억 건 부하 시험을 완료한 것은 아닙니다.** 실제 처리량·구조 다양성·생물종 범위·예산에 따라 목표 전에 종료될 수 있습니다. 현재의 SQLite 한 호스트 구현을 다중 서버 분산 시스템이라고 표시하지 않습니다. 저장량 실측과 대규모 운영 한계는 [저장 계층 문서](discovery-storage.md)에 있습니다.

대량 단계는 결정적인 화학 계산이며 분자마다 LLM·AF3·QPU를 호출하지 않습니다. 기존 GPT-6 Astra 오케스트레이션과 AlphaFold 3·IBM Quantum 연결은 선택된 소수 후보의 정밀 분석에 사용합니다. 새 후보에는 `affinity: null`, `novelty: not_assessed`를 기록합니다. 신규성·표적 결합·독성·효능·합성과 실험 검증은 별도 과제입니다.

## 이번 실제 실행 결과

- LOTUS: 709,740행 처리, 227,265개 구조·694,270건 출현 기록 보존.
- COCONUT: 738,827행 처리, 해당 출처의 고유 구조 728,421개·출처 기록 738,823건; 구조 검증 제외 4행.
- ChEMBL: 승인 이력 4,225행 처리, 구조가 제공되고 해석된 3,417개 보존; 구조 누락·검증 제외 808행. 원본 페이지는 보존.
- 전체 원천을 합쳐 구조를 중복 제거한 결과: **766,417개 구조·1,436,510건 출처 기록**.
- 첫 캠페인: 천연물 500종×약물 3종, 6,245회 시도·937개 보존, 조합 소진.
- 감초속 확장 캠페인: 천연물 800종×표준화 후 약물 93종, 100,000회 시도·37,966개 유효 구조 제안·4,895개 보존, 시도 예산 종료. 생성 계산 328.999초이며 부모 준비·다운로드 시간은 별도.
- 두 캠페인의 보존 수 합계는 5,832개이고 캠페인 사이의 같은 구조까지 다시 제거하면 **5,741개**입니다. 화면은 캠페인별 합계에 중복 가능성을 표시합니다.
- 자동 테스트 247개, Python lint, 프런트엔드 빌드, 실제 브라우저의 검색/원문/분류/3D/내보내기/모바일 검증 통과. 서버 재시작 전후 후보 수와 커서를 대조하고 재개를 확인했습니다.

상위 후보 1,000개의 JSONL은 `runtime/discovery/shortlist-herbal-top1000.jsonl`에 있습니다. 순서는 QED 기준이며 결합 친화도나 효능 순위가 아닙니다. 전체 구조·출처 및 실제 실행 계수는 [기계 판독용 검증 기록](discovery-verification.json)에 있습니다.
