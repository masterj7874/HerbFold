# UniProt 표적 조회·등록과 AF3 계산

분자 스튜디오의 **단백질 표적 · UniProt ID**에서 다른 단백질의 서열을 조회하고 등록할 수 있습니다. 기본 표적인 사람 COX-2 `P35354`의 기존 서열과 계산 기록은 유지됩니다.

1. UniProt accession을 입력하고 조회·적용 버튼을 누릅니다. 예를 들어 `P00533`은 사람 EGFR 단백질입니다.
2. 표시되는 단백질 이름, 생물종, 서열 길이와 원문 링크를 확인합니다. 생물종이나 isoform이 다르면 계산에 들어가는 서열도 달라집니다.
3. **이 성분의 AF3 계산 → 입력 준비**에서 선택 성분과 해당 단백질 서열로 입력을 만듭니다.
4. 입력과 실행 조건을 확인하고 계산을 실행합니다. 표적 조회·등록·적용만으로 GPU 계산이 시작되지는 않습니다.

등록된 표적은 앱 저장소에 영구 보존되므로 다음 선택이나 서버 재시작 후 다시 다운로드할 필요가 없습니다. 동일 ID를 다시 등록해도 저장된 서열을 자동으로 덮어쓰지 않습니다. UniProt의 주석 검토 상태는 서열 출처 정보이며, 실험적으로 확인된 결합이나 AF3 구조 정확도를 뜻하지 않습니다.

대표 서열의 6자리·10자리 접근번호와 `P00533-2` 같은 정확한 아이소폼 ID를 지원합니다. 아이소폼은 UniProt 항목의 아이소폼 매핑과 FASTA 헤더를 함께 확인하며 대표 서열로 대체하지 않습니다. 이전 접근번호는 UniProt의 명시적인 별칭·병합 정보가 확인될 때만 현재 기본 접근번호로 연결합니다. 별칭의 아이소폼 번호를 임의로 새 기본 접근번호에 옮기지는 않습니다.

계산을 준비하면 실제 사용한 단백질 서열, SHA-256과 출처 정보를 해당 작업에 고정합니다. 저장된 결과와 진단은 그 작업의 입력 서열을 기준으로 확인하므로, 표적 선택이나 등록 목록이 바뀌어도 이전 결과가 다른 단백질의 결과로 표시되지 않습니다. MSA 검색 캐시도 실제 서열과 검색 조건에 맞는 경우에만 재사용합니다.

등록되지 않은 표적, 존재하지 않는 ID, 조회 실패와 지원하지 않는 서열은 명확한 오류로 표시합니다. 임의의 다른 단백질이나 기본 COX-2로 대체하지 않습니다. 표적 선택은 AF3 예측의 단백질 입력을 지정하는 기능이며, 해당 성분의 결합 상대를 자동으로 찾아내거나 약효를 확정하는 기능은 아닙니다.

등록은 이 플랫폼의 AF3 입력 형식에 맞는 표준 아미노산 문자와 `X`만 허용하며, 서열 길이는 10,000개 이하로 제한합니다. 이 입력 한도는 해당 크기의 계산에 필요한 GPU 메모리가 확보됐다는 뜻은 아닙니다. 계산 모드·서열 길이·실행 환경에 따라 별도의 준비 검사와 실제 실행 결과를 확인해야 합니다.

| API | 동작 |
| --- | --- |
| `GET /api/molecular/targets` | 저장된 표적 목록 |
| `GET /api/molecular/targets/{accession}` | 등록된 표적과 서열 조회 |
| `POST /api/molecular/targets/register` | `{"accession":"P00533"}`로 UniProt 조회·등록; 이미 등록되어 있으면 재사용 |
| `POST /api/molecular/predictions/prepare` | 등록된 `target_accession`과 선택 성분으로 AF3 입력 준비 |

공식 자료: [UniProt accession](https://www.uniprot.org/help/accession_numbers), [대표 서열과 isoform](https://www.uniprot.org/help/canonical_and_isoforms), [P00533 원문](https://www.uniprot.org/uniprotkb/P00533/entry), [AF3 입력 형식](https://github.com/google-deepmind/alphafold3/blob/main/docs/input.md).

2026-09-14 실제 조회 검증에서는 `P00533`의 1,210개 아미노산과 `P00533-2`의 405개 아미노산을 구분해 등록했습니다. 별도 임시 저장소에서 두 표적과 아스피린의 실제 AF3 입력·준비 검사를 통과했고, 입력 서열·해시·출처의 일치와 저장소 재개 후 등록 보존을 확인했습니다. 새 GPU 추론은 제출하지 않았습니다. [실제 조회·입력 검증 보고서](uniprot-target-live-verification.json).

소프트웨어 검증은 관련 백엔드 256개와 프런트엔드 49개 테스트, Ruff 및 TypeScript·정적 빌드를 통과했습니다. 별칭·아이소폼 일치, 등록 동시성·재사용, 저장 기록 손상, 느린 분할 응답의 시간 제한, 이전 작업의 고정 서열과 결과 검증을 포함합니다. 서버를 `0.0.0.0:9018`에 적용한 뒤 기존 완료 작업의 3D 구조와 상세 진단이 정상 조회되고 모든 기존 작업 상태가 보존됨을 확인했습니다. [서버 적용 보고서](uniprot-server-verification.json).

실제 브라우저에서는 이미 등록된 EGFR을 재사용해 메타데이터·서열 미리보기, 표적 적용·기본 표적 복귀, 새로고침과 인증 재연결, 데스크톱·모바일 표시를 확인했습니다. 격리된 응답 재현으로 조회 실패·늦은 응답·30초 시간 초과 후 복구도 검증했습니다. JavaScript 오류와 검증 브라우저의 AF3 준비·실행 요청은 모두 0개입니다.
