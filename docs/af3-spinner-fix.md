# AF3 실행·결과 화면의 무한 대기 수정 — 2026-09-14

작업 `308e4b99d57a432ebfd11c90a67ec02c`은 CPU MSA·템플릿 검색을 465.72초에 완료한 뒤 GPU 추론에서 메모리 할당 실패를 반복했습니다. 당시 두 GPU에서 vLLM 작업이 각각 89,630MiB를 사용했고, 선택된 GPU에는 다른 영상 분석 작업도 실행 중이었습니다. AF3 로그에는 약 307MiB의 할당까지 실패하는 기록이 수분간 반복됐습니다. 단순히 로그가 조용하다는 이유로 정지한 것으로 판단하지 않았습니다.

복구 과정에서 이 AF3 추론 프로세스만 중단하고 상태를 `interrupted`로 기록했습니다. 중단 이유와 이전 기록은 작업 디렉터리의 `spinner_recovery.json`, `before_spinner_recovery.json`에 보존했습니다. 다른 서비스는 변경하지 않았습니다. 기존 입력·로그와 검증된 단백질 검색 캐시는 유지되며, 실제 재사용 검사도 통과했습니다. 보존된 검색 결과는 unpaired MSA 11,229개, paired MSA 17,801개, 템플릿 4개입니다. GPU 메모리를 확보한 뒤 같은 조건으로 다시 준비하면 검증된 검색 특징을 재사용할 수 있습니다. 이번 수정에서 새 GPU 추론을 제출하지 않았습니다.

화면의 상태 조회와 로그 조회를 분리했습니다. 이전에는 두 응답을 함께 기다렸기 때문에 로그 하나가 지연되면 계산 완료도 반영하지 못했습니다. 이제 조회마다 15초 제한을 두고 연결 오류와 마지막 확인 상태를 구분하며 자동으로 다시 조회합니다. 준비·실행 응답이 지연되면 접수 확인을 안내하고, 자동으로 중복 제출하지 않습니다. 성분 전환 시 이전 요청·대기 상태도 정리합니다.

현재 CPU/GPU 단계, 실제 단계 경과 시간, 완료된 단계의 소요 시간, 마지막 상태 확인 시각을 표시합니다. 서버는 실행 중 상태를 10초마다 기록하고 GPU 메모리 할당 경고를 화면에 전달합니다. 최종 예외와 일시적인 할당 경고를 구분하며, 경고가 있더라도 정상 종료한 계산을 실패로 판정하지 않습니다.

새로운 GPU 할당 실패 메시지만 계속 나타나고 다른 로그 진행이 없는 경우 기본 180초의 재시도 예산 후 해당 추론만 중단하고 `resource_retry_timeout`을 기록합니다. CPU 계산, 로그 침묵, 오래된 경고의 반복 조회는 중단 근거가 아닙니다. 다른 진행 메시지·관측 공백·로그 교체/잘림이 있으면 연속 실패 관측을 초기화합니다. 이번 실제 로그를 읽기 전용으로 재현했을 때 180초 조건에서 중단 기준이 충족됨을 확인했습니다. [실제 로그 재현 결과](af3-allocation-retry-replay.json).

관련 백엔드 테스트 95개와 프런트엔드 테스트 43개, Python lint, TypeScript 검사와 정적 빌드를 통과했습니다. 메모리 할당 경고 뒤 정상 완료, 명확한 GPU OOM, CPU 메모리 실패, 상태·로그 응답 지연, 자동 재연결, 성분 전환을 검증했습니다. [실행·재시도 설정 안내](af3-calculation-workflow.md).
